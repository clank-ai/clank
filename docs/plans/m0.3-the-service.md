# M0.3: the service, its API, the commands and the machine component: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (executed natively in the session that
> wrote it). As for M0.2, this plan gives the files, interfaces and tests by name and intent; the code is in the
> commits, written test-first.

**Goal:** `clank serve` runs the Clank service: the kernel, the API (every route behind the local token), the one event
stream, the generic routes for every kind, and the first component, `machine` (the machine profile and the checks of
`clank doctor`). `clank status`, `clank stop`, `clank events --follow`, `clank questions`, `clank operations` and
`clank records` are clients of it; `clank doctor` also works without it.

**Architecture:** `clank/kernel/core.py` assembles a `Kernel` (home, clock, store, events, settings, questions,
operations, the registry) from the kernel's parts and every component's declarations. A component
(`clank/kernel/components.py`) declares its name, the components it uses, its kinds, event types, and how to build its
part (operation types, routes, a background task). `clank/kernel/api.py` builds the FastAPI application;
`clank/kernel/service.py` runs it with Uvicorn beside the kernel's housekeeping (expiring questions, reloading edited
settings, pruning old events) and records `service.started` and `service.stopped`. `clank/client.py` is the one HTTP
client of the Python clients (the commands now, the console in M0.5).

**Tech Stack:** FastAPI 0.143 and Uvicorn 0.54 (decision 0016), httpx 0.28 (decision 0024, new), psutil 7.2 (decision
0025, new), click (decision 0023).

**Spec:** [design 0002](../design/0002-the-foundation.md) §2.1 (a component), §2.7 (callers and access), §2.14 (the
API), §2.15 (commands), §3.2 (M0.3); design 0001 §2 (the machine profile), §4.7 (the computer's settings that matter),
§7.3 (what the guide's first step checks).

## Global Constraints

- Everything of M0.1 and M0.2's global constraints holds.
- Every route needs the local token, reads included; requests addressed to a host name other than the service's own are
  refused; no CORS headers; a token never appears in a URL or a record (design 0002 §2.7).
- Errors have one shape: `{"error": {"code", "message", "where"}}` (design 0002 §2.14).
- Every route declares its access level, and a test fails when one does not.
- A component uses another only through that one's `service.py`, only if it declares it, never in a cycle; the kernel
  uses no component (decision 0019) — checked by a test that reads every import.
- On Windows the service runs where it is started (natively, for the owner's console and VS Code); where it runs once
  engines need WSL is settled in M1's design. Ruling: cost if wrong: the service moves into WSL in M1, behind the same
  connection file and API.

## Review Focus

1. **A browser page on this machine calls the API** (DNS rebinding, a forgotten token): refused. Pinned by
   `test_every_route_refuses_a_call_without_the_token` and `test_a_request_addressed_to_another_host_is_refused`.
2. **The service is started twice, or its port is taken by another program:** a clear message, no second service.
   Pinned in Task 4.
3. **A client follows the event stream while events arrive from other threads:** nothing lost, nothing twice. Pinned by
   `test_the_stream_sends_the_backlog_then_live_events_without_gaps_or_repeats`.
4. **`clank doctor` on a machine without an NVIDIA GPU, WSL or Docker:** warnings, not crashes. Pinned in Task 5.
5. **The service stops while an operation runs:** the next start marks it interrupted (M0.2's recovery, now wired into
   the service's start). Pinned in Task 4.

### Task 1: Components, the kernel assembled, and the import boundaries

**Files:** decision records `0024-httpx-for-clients.md`, `0025-psutil-for-the-machine.md` and their index rows;
`pyproject.toml` (fastapi, uvicorn, httpx, psutil); `clank/kernel/components.py`, `clank/kernel/core.py`,
`clank/components/__init__.py`, `clank/registry.py` (components join); tests `tests/kernel/test_core.py`,
`tests/test_architecture.py`.

**Interfaces:** `Component(name, summary, uses=(), kinds=(), event_types=(), migrations_package=None, build=None,
commands=None)`; a component's part (what `build(kernel)` returns) may offer `operation_types()`, `router()` and
`async run()`. `Kernel` (`home`, `clock`, `store`, `events`, `settings`, `questions`, `operations`, `kinds`, `parts`)
and `open_kernel(home, clock, components) -> Kernel` (migrates, loads settings, builds the parts, registers their
operation types); `Kernel.close()`. `registry.components()`.

**Tests:** opening a kernel creates the database, loads the settings and builds every part; a component's operation
types join the kernel's; the import test: the kernel imports no component, a component imports another only through its
`service.py` and only if it declares it, the declared uses have no cycle.

### Task 2: Callers and access

**Files:** `clank/kernel/access.py`; test `tests/kernel/test_access.py`.

**Interfaces:** `local_token(home) -> str` (created once, `state/local.token`, readable only by the user where the
platform allows); `Connection(url, pid, started, version)`; `write_connection(home, connection)`,
`read_connection(home) -> Connection | None`, `remove_connection(home)`; `client_actor(name) -> Actor`.

**Tests:** the token is created once and then kept; it is long and random; the connection file round-trips and is
removed on stop.

### Task 3: The API

**Files:** `clank/kernel/api.py`, `tools/apidoc.py` and the generated `docs/API.md`; tests `tests/kernel/test_api.py`,
`tests/tools/test_apidoc.py`, one test in `tests/test_repository.py`.

**Interfaces:** `create_app(kernel, *, token, port, stop) -> FastAPI` with, under `/api/v1/`: `GET service`,
`POST service/stop`, `GET kinds`, `GET records/{kind}`, `GET records/{kind}/{id}`, `PUT records/{kind}/{id}` (settings:
`{values, base}`), `DELETE records/{kind}/{id}?base=`, `GET history`, `GET events` (Server-Sent Events: `after` or the
`Last-Event-ID` header, `types`, `subject_kind`, `subject_id`, `follow`), `GET questions`, `POST
questions/{id}/answer`, `GET operations`, `POST operations/{id}/cancel`, `POST operations/{id}/retry`, `POST
presence`, `GET openapi.json`; each component's routes. The client names itself in `X-Clank-Client` ("console",
"vscode", "cli"); the actor of what it does is "you (<client>)".

**Tests:** every route refuses a call without the token; a request addressed to another host is refused; every route
declares its access level; errors have one shape; kinds are listed with their labels, help and schemas; a settings
record is read, written over its revision, refused over a stale one (with the current version); state records are read
through the same routes; answering a question records the client; the stream sends the backlog then live events
without gaps or repeats, and says `reset` to a client behind the pruned events; `docs/API.md` is up to date.

### Task 4: The service

**Files:** `clank/kernel/service.py` (`Service`), `clank/cli/service.py` (`serve`, `stop`, `status`); tests
`tests/kernel/test_service.py`, `tests/cli/test_service_commands.py`.

**Interfaces:** `Service(home, clock).run()`: opens the kernel, recovers interrupted operations, takes the port (a
clear error if it is taken, or if a service already answers), writes `state/connection.json`, serves the API with
Uvicorn beside the housekeeping (questions expired, edited settings reloaded every two seconds; events pruned hourly),
runs each part's `run()`, and on stop records `service.stopped` and removes the connection file. `clank serve
[--background]` (the background form starts a detached service, its output in `logs/service.log`, and waits until it
answers); `clank stop`; `clank status`.

**Tests:** the service starts on a free port, writes its connection file, answers with the token, refuses without it,
and stops on request, removing the file; a second service on the same CLANK_HOME is refused; an operation cut short by
a stop is interrupted at the next start; the housekeeping expires questions and reloads an edited settings file.

### Task 5: The machine component and `clank doctor`

**Files:** `clank/components/machine/` (`component.py`, `kinds.py`, `detect.py`, `checks.py`, `service.py`, `api.py`,
`cli.py`); tests under `tests/components/machine/`.

**Interfaces:** `MachineProfile(Settings)` (`config/machine.json`): system, Python, WSL, CPU, cores, memory, GPUs,
Docker, when detected. `detect(run=subprocess) -> MachineProfile`. `Check(id, title, run)`, `CheckResult(status:
passed|warning|failed|skipped, detail, fix)`; the checks: Python version, CLANK_HOME writable, the state database's
integrity, free disk, an NVIDIA GPU, WSL 2 (Windows), hardware-accelerated GPU scheduling off (Windows, design 0001
§4.7), Docker installed, Docker running, the API's port. The part: operation `machine.doctor` (steps detect, check;
result: the checks), routes `GET machine`, `POST machine/doctor`. `clank doctor [--json]` runs the checks itself, with
or without the service.

**Tests:** detection reads the system with the commands faked, and without a GPU, WSL or Docker it says so; each check
passes, warns or fails as its facts say, and the platform-specific ones are skipped elsewhere; `clank doctor` prints
each check and how many passed, as text and as JSON; the doctor operation records the profile and the checks.

### Task 6: The commands

**Files:** `clank/client.py`, `clank/cli/records.py` (`events`, `questions`, `operations`, `records`); tests
`tests/cli/test_commands.py`.

**Interfaces:** `Client.connect(home=None) -> Client` (reads the connection file and the token; `NotRunning` with "start
it with `clank serve`" otherwise); `get`, `post`, `put`, `delete`, `stream`. Commands: `clank events [--follow]
[--type T] [--limit N]`, `clank questions [answer ID OPTION [--text]]`, `clank operations [cancel ID | retry ID]`,
`clank records kinds | list KIND | show KIND ID`, each with `--json`.

**Tests:** each command prints readable text and, with `--json`, JSON; answering a question from the command line records
"you (cli)"; with no service running, a command says how to start it.

### Task 7: Records up to date

**Files:** `AGENTS.md` (layout: components, the client; commands), `README.md` (status), `docs/ROADMAP.md`,
`docs/plans/README.md`, the generated documents.

## Rulings made while building

- **Setup.** As in M0.2: work on `main`, a self-review at the end, interfaces and tests in the plan. The service runs
  where it is started (natively on Windows, for the owner's console and VS Code) until M1 decides where engines need
  it. Cost if wrong: it moves into WSL in M1, behind the same connection file and API.
- **Task 3.** The event stream treats the notification of a kept event as a wake-up only, and reads what is new from
  the database in id order: commits are serialized but their after-commit callbacks are not, so two threads could
  deliver out of order. Cost if wrong: one query per wake-up.
- **Task 3.** Decision 0026 supersedes 0024: Starlette 1.7's test client deprecates httpx for httpx2, its maintained
  successor. Cost if wrong: one import name.
- **Task 3.** FastAPI 0.143 keeps included routers as one lazy wrapper, so the access tests read the API's own OpenAPI
  description, and the token check is a standard HTTP Bearer security scheme named after the access level, which the
  description shows on every operation. The first access tests had passed vacuously; the empty API page showed it.
  Cost if wrong: none.
- **Task 4.** The minimal client (`clank/client.py`) was built in Task 4, not Task 6, because `serve`, `stop` and
  `status` need it. On Windows the virtual environment's `python.exe` is a launcher whose child is the interpreter, so
  tests compare the process id the service writes itself, `start_detached` waits for a connection file written after
  the launch, and the test helper stops a service through its API before ending the process tree. The service's own
  declarations moved to `clank/kernel/service_kinds.py`, which breaks an import cycle. Cost if wrong: none.
- **Task 5.** A component's `commands()` returns a list of click commands (the machine component's is `clank doctor`).
  Cost if wrong: none.
- **After Task 7.** CI on Linux failed where Windows passed: detection read Windows' registry whenever a test asked for
  Windows' commands, the disk check read the runner's own free space, and two Windows-only names were unguarded for the
  type checker. The system and processor now always describe this computer, the free space is a fact the callers
  measure, and `tools.check` type-checks as on Windows and as on Linux, so a working copy catches what CI would. Cost if
  wrong: none.

## Final review

A self-review of all of M0.3 against design 0002 §2.1, §2.7, §2.14, §2.15 and the Review Focus above: each Review Focus
item has its test, and CI passed (run 38194881118). No important finding. Deferred (minor): two services started at
the same moment on different ports could both run for one CLANK_HOME (a lock file would close that; one service per
home holds otherwise); `history` and `operations` accept any `limit`; the generic record routes read only the kernel's
own state kinds, so a component's state kind will declare its reader when the first one comes.
