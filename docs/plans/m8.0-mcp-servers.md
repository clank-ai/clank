# M8.0: MCP servers, added the standard way: implementation plan

> Ahead of M8, at the owner's request (2026-10-13): "make sure we have the ability to add MCP servers. This should be
> doable from inside the clank menu as well as from the command line ... adhere to the standards used by all other
> harnesses". As for M1, this plan gives the files, interfaces and tests by name and intent; the code is in the
> commits, written test-first.

**Goal:** the `tools` component (design 0002 §1) with its first kind, `mcp-server`: MCP servers added, listed, shown,
checked and removed from the command line (`clank mcp`, the syntax of `claude mcp` and `codex mcp`) and from the
console, kept so that M8's tool hub and M5's agents can run them later.

**Spec:** design 0002 §1 (the tools component), §2.11 (the library: where an item came from is recorded; a project's
own items are offered, never trusted), §3.4; decision 0020 (enforced where it can be stopped).

## Global Constraints

- The command line follows the standard other harnesses share: `clank mcp add [options] NAME -- COMMAND [ARGS...]`
  for a server Clank starts (stdio), `clank mcp add --transport http NAME URL` for a remote one; `-e KEY=VALUE`,
  `-H "Name: value"`, `-s user|project`; `add-json`, `list`, `get`, `remove`. A project's servers are its `.mcp.json`
  (`{"mcpServers": {...}}`), the file other harnesses read.
- Values given with `-e` and `-H` are secrets: they live in `CLANK_HOME/secrets/`, readable only by the user, and
  never in a settings file, an event, a log or an answer (shown as `•••`). A project's `.mcp.json` holds what the user
  writes there, as the standard has it.
- Nothing here runs a server except `check`, which the user asks for, on this machine, and which ends it.
- Nothing from the prototype (the owner's rule of 2026-10-13: the prototype is a template only).

## Review Focus

1. **A command whose own options look like Clank's** (`-- uvx pkg --port 3`): everything after `--` is the server's.
2. **A name used twice** (user and project): both are listed, each with its scope; `get` and `remove` say which.
3. **A secret given on the command line**: it reaches no file but the secrets folder, and no event.
4. **A server that never answers** (`check`): ended at its time limit, saying so.
5. **The owner's literal `clank mcp add myproject --myproject-mcp`**: refused, showing the form with `--`.

## Rulings made while building

- **Ahead of M8, without its own design document.** The owner asked for MCP servers now, in the standard form; this
  plan carries the few choices M8's design would otherwise make, as rulings here. Cost if wrong: M8's design revisits
  them.
- **The command line copies `claude mcp` and `codex mcp`.** `add [options] NAME -- COMMAND [ARGS...]`, `-e`, `-H`,
  `-s user|project`, `add-json`, `list`, `get`, `remove`; Clank adds `check`. Without `--`, the first word after the
  name is the command and options Clank does not know go with it (`ignore_unknown_options`), so a server's own option
  that is also one of Clank's (`-e`, `-s`, `-t`, `-H`) needs `--`, as in the other harnesses. A command starting with a
  dash is refused with the form that has `--` (the owner's first try was `clank mcp add myproject --myproject-mcp`).
  A URL alone implies http (Gemini's way; Claude Code asks for `--transport http`). Cost if wrong: one more inference.
- **Scopes: `user` (the default) and `project`.** Claude Code's default is `local` (this project, private), which needs
  workspaces (M4); until then a server is yours everywhere, or the project's in its `.mcp.json`. Cost if wrong: a
  default that changes once workspaces exist.
- **Your servers' environment and header values are secrets** (the kernel's secrets part, design 0002 §2.8, built here
  with its first use), shown by name and last four characters; a project's are in its `.mcp.json`, as the standard
  keeps them. Cost if wrong: a value meant to be plain (`LOG_LEVEL=debug`) shows only its last four characters.
- **A name is new in its place whatever its case**, since Windows does not tell `Foo.json` from `foo.json`. Cost if
  wrong: two servers named apart only by case are refused.
- **`mcp.changed` is recorded on every add and remove**, so every client hears of a change to a project's `.mcp.json`
  too (no settings event covers that file). Cost if wrong: none.
- **`check` runs the server on this machine** (stdio) or reaches it (http), on the user's request only; checking an
  `sse` server is not built (it is kept). M8 runs servers in their own containers behind the tool hub (design 0002
  §1). Cost if wrong: a server that only runs inside a container cannot be checked here until M8.
- **The console's page is `F3`**, the first key free after the function keys the console already uses (F1 help, F2
  launch options). Cost if wrong: a key to move when the layout and keys are designed (M2).

## Final review

Self-review against the review focus: a command whose own options look like Clank's goes after `--` (the CLI test with
`-- uvx some-mcp --port 3 -e x`); a name in both places is asked about (test_servers); a secret given on the command
line reaches no file but the secrets folder and no event (test_servers, test_secrets, and the CLI tests' output); a
server that never answers is ended at its time limit, saying so (test_mcp); the owner's literal command is refused with
the `--` form (test_mcp_commands).

Deferred minors:
- The console's add form has one field for the environment (KEY=VALUE, space-separated) or, for a URL, the headers
  (`Name: value; ...`); two fields would read more plainly.
- A project's `.mcp.json` entries that use `${VAR}` expansion (Claude Code's) are kept as written; Clank does not
  expand them when it checks the server.
- The kernel writes any settings record name as a file name without checking it; the tools component checks its own
  names, but the generic settings routes do not yet (found here, not caused here).
