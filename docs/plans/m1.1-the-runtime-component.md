# M1.1: the runtime component, its records and its engine adapters: implementation plan

> As for M0.2-M0.6, this plan gives the files, interfaces and tests by name and intent; the code is in the commits,
> written test-first.

**Goal:** the runtime component (`clank/components/runtime/`) with its settings kinds (presets, hosts, model files,
the runtime's own settings), the model catalog, the engine adapter kind with its two adapters (KVMem/llama.cpp
v0.16.0-rc1 and NInfer RTX 5080 v1.4), each declaring its options and planning the exact command line and memory of
a preset; `clank preset list|show` and the API's preset and engine routes. Nothing starts an engine yet (M1.2-M1.3).

**Architecture:** design 0003 §3-§4. An engine adapter is an `Adapter` (design 0002 §2.10) of the new kind `engine`:
`options(version)` lists its launch options (design 0001 §3.1's fields), `validate(options, version)` says what is
wrong with a preset's options, and `plan(preset, model, host, port)` gives the argv, environment, folder and the memory
estimate. Recordings of what each engine printed at its version (its `--help`, its startup log, its `/v1/models`)
drive the contract test; NInfer's first recording is written from its source at v1.4 until M1.4 records the real one.

**Tech Stack:** what M0 uses; no new dependency.

**Spec:** [design 0003](../design/0003-the-runtime.md) §1, §3, §4, §5, §7.3; design 0001 §2, §3.1-3.7; decisions 0010,
0030, 0031.

## Global Constraints

- Everything of M0's global constraints holds.
- Tracked files hold no machine's specifics: no GPU identifier, no home path, no host name; this machine's facts live
  in the recordings only as the engines printed them, with paths made relative or generic.
- An option's `maps_to` is exactly what the engine receives; a plan is exactly what would run.

## Review Focus

1. **An option the engine does not have at that version, or a value outside its range:** the preset is refused, naming
   the option and why. Pinned in Task 2.
2. **A preset for an engine version no adapter knows:** refused with the versions that are known. Pinned in Task 2.
3. **The published NInfer profile and the prototype's daily KVMem profile:** their plans are exactly the command lines
   their authors run. Pinned in Tasks 3 and 4.
4. **A preset that leaves an option at its default:** the flag is not repeated on the command line unless the engine's
   default differs from Clank's. Pinned in Task 3.
5. **A model file the catalog does not know, or a format the engine cannot read:** refused before any plan. Pinned in
   Task 5.

### Task 1: The runtime component and its settings kinds

**Files:** `clank/components/runtime/{__init__,component,kinds,service,api,cli}.py`, `clank/components/__init__.py`,
tests `tests/components/runtime/test_kinds.py`,
`test_presets_api.py`.

**Interfaces:** kinds `Preset` (`preset/1`: name, engine, engine_version, model, format, options, slot, notes),
`Host` (`host/1`: adapter, distro, folder), `ModelFile` (`model-file/1`: model, format, host, path), `RuntimeSettings`
(single, `runtime/1`: slots, port, tight_mib, start_seconds, health_seconds); `Runtime` (the part) with `presets()`,
`engines()`; routes `GET /runtime/presets`, `GET /runtime/presets/{id}`, `GET /runtime/engines`; commands
`clank preset list`, `clank preset show NAME`.

**Tests:** a preset file is read and listed with its engine and model; an unknown field is refused with its line; the
routes list presets and engines; the commands print them, and JSON with `--json`.

### Task 2: Options and the engine adapter kind

**Files:** `clank/components/runtime/adapters/{__init__,engine}.py`; tests `tests/components/runtime/test_options.py`,
`tests/contract/test_engine.py`.

**Interfaces:** `EngineOption` (key, label, help, kind, choices, minimum, maximum, unit, default, scope, maps_to,
memory, requires, conflicts, tested), `EngineVersion` (name, supports), `MemoryEstimate` (weights, kv, buffers,
overhead, `total`), `Plan` (argv, env, cwd, port, memory, notes), `EngineAdapter` (`NAME`, `LABEL`, `PROGRAM`,
`VERSIONS`, `FORMATS`, `options(version)`, `validate(options, version) -> list[str]`, `plan(...)`, `ready(line)`,
`memory_report(lines)`), the kind `ENGINES`.

**Tests:** an unknown option, a value outside its range or choices, a `requires` not met, an unknown version, are each
refused with a sentence that names them; the contract runs every adapter against each of its recordings.

## Rulings made while building

- **Setup.** As in M0: work on `main`, a self-review at the end, interfaces and tests in the plan. Design 0003 is
  built before the owner read it, at the owner's instruction (its status says so). Cost if wrong: rework where the
  owner's review differs.
- **Task 1.** A preset's name is its record's title (every settings record has one) and its id its file's name; it
  has no `format` field, since each engine reads one format. A host's folder is `clank_folder` (`folder` is already
  the settings' own). A change to the preset a slot runs applies at its next start (`ON_CHANGE`), not refused as
  design 0003 §3 first said; §3 now says so. Each preset as clients see it carries its problems. Cost if wrong: none.
- **Task 2.** What an option maps to is declared per value (flags, and `env:` variables), and the command line is made
  from those declarations alone, so what the console shows is what runs; a flag that only repeats the engine's own
  default is left out, and so is a default whose requirement the preset does not meet (the image tokens of a preset
  without vision). Cost if wrong: none.
- **Tasks 2-3.** `engine.py` and `kvmem.py` were written before their tests; each test was then shown to fail against
  a deliberately broken module before the code was restored. Tasks 4 and 5 were test-first. Cost if wrong: a test that
  checks less than it seems, which the breaks argue against.
- **Task 3.** Clank's defaults for KVMem are the prototype's daily values, so the daily preset holds only its vision. No
  `CUDA_VISIBLE_DEVICES`: the prototype's names this GPU's identifier, which is one machine's, and this machine has one
  GPU. Cost if wrong: on a machine with two GPUs, an option to choose one is needed.
- **Task 4.** NInfer's first recording is written from its source at v1.4 with its release's measurements, until M1.4
  records it from the build; the sizes its memory estimate uses are derived from the releases' numbers until a launch
  here measures them. Cost if wrong: an estimate off by some hundreds of MiB until then.
- **Task 5.** Clank ships three presets: *daily 262K* (KVMem), *NInfer 128K as published*, and *NInfer 128K fitted*
  (KV capacity `auto`, vision off), which suits any GPU that also drives a desktop. The vision projector's revision is
  no longer known, so Clank lists it but would not download it. Cost if wrong: none.

## Final review

A self-review of M1.1 against design 0003 §3-§5 and §7.3 and the Review Focus above: each Review Focus item has its
test (a wrong option or value, an unknown version, the published and the daily command lines, defaults left out, an
unknown model or format); both adapters pass the contract against their recordings; CI passed. No important finding.
Deferred (minor): NInfer's recording is written, not recorded (M1.4); NInfer's sizes are derived, not measured (M1.6);
for `kv_capacity: auto` the estimate takes the whole context as the KV cache's upper bound; an option's need of a model
feature (vision needs a projector or a vision tower) is not checked against the catalog yet (M1.3, with the files on a
host).
