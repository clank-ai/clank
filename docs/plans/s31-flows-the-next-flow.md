# Flows, step 9: the next flow: implementation plan

> At the owner's request (2026-10-20, through the build's coordinator): decision 0058 (design 0013 §3, the owner's
> Choice) says INTEGRATE's brief starts a next flow, linked to this one, after the last gate; nothing built it. As for
> the earlier plans, the files, interfaces and tests by name and intent; the code is in the commits.

**Goal:** [design 0013](../design/0013-flows.md) §3, §10 and §14 step 9 (added 2026-10-20): once a flow's last gate is
approved, a new flow is made from Clank's template with its INTEGRATE's brief as its YOU box's file, linked both ways
to the flow it came from, and the owner is asked whether to run it now; it never starts without their answer unless
the flow says so; `clank flow next` shows it, makes it, or runs it.

**Architecture:** A new part of the component, `following.py` (`Following`), built by the flows' service beside the
runner, so the runner itself does not change: it hears the runner's events. On `flows.run_ended` done, when the run's
last box was a GATE it approved, it makes the next flow (`next_values`, a pure function of this flow, its run's
INTEGRATE, the brief's text and Clank's template), writes it and this flow's link through the settings, records
`flows.next_made`, and asks its question (*run it now*, *later*), about the new flow, which survives a restart. Its
answer, heard through the questions' listeners, starts the new flow's run. On `flows.run_started` of a flow's first
run whose `follows` names a brief, it copies the brief into the flow's YOU box's file, unless the owner changed that
file since the flow was made (`flows.next_brief` says which). The flow's file gains `next_flow` (ask, run, off),
`follows` and `next`. The routes `GET` and `POST /flows/{workspace}/{name}/next` and `clank flow next NAME [--make]
[--run]` serve the command line.

**Tech stack:** Python 3.12, AnyIO, FastAPI, click, pytest; the runner's rig of plan s24, the fake bridge.

**Spec:** [design 0013](../design/0013-flows.md) §2, §3, §6, §10, §11 and §14 step 9 (revised 2026-10-20); decisions
[0058](../decisions/0058-integrate-starts-the-next-flow.md) and
[0091](../decisions/0091-the-next-flow-is-made-when-the-last-gate-is-approved.md);
[0066](../decisions/0066-a-flow-is-a-settings-file-in-clanks-home.md) (a flow is a settings file).

## Global Constraints

- Nothing runs OpenCode, a container, Docker or a model: the fake bridge and synthetic folders only; nothing opens a
  window.
- No new dependency. Tests first, each test file's docstring naming the design sections it verifies, test names
  sentences.
- The runner is not changed (another build changes it now); the next flow hears its events.
- The owner is the sole author of every commit (no trailer). The generated files are regenerated by `uv run python -m
  tools.check --fix`.

## Claude's calls (2026-10-20)

1. **The last gate** is the last box in the order the boxes run, when it is a GATE, approved in a run that then ended
   done. **INTEGRATE's brief** is the file named `NEXT.md` among the writes of the last INTEGRATE before it, else the
   last of its files when it writes two or more; none otherwise, or when the file is not in the folder (an event says
   why, and `clank flow next` too).
2. **The new flow** is Clank's template with: its title, the brief's first Markdown heading, else "<title>, next"; its
   workspace, this flow's; its defaults' model, this flow's; its YOU box saying where its brief comes from; `follows`
   = {flow, run, by (the INTEGRATE), brief (its path), replaces (the fingerprint of the YOU box's first file when the
   flow was made; empty when it was not in the folder)}. Its id is `<workspace>/<base>-<n>`, `<base>` this flow's name
   less a trailing `-<digits>`, `<n>` the first number from 2 (or this flow's number plus one) that no flow of the
   workspace takes.
3. **This flow's `next`** names the new flow, written through the settings like any change (a write refused because
   the file changed meanwhile is tried once again on the file as it is).
4. **The question**, about the new flow: "<title> is done: run the next flow, <next title>, now?", its options *run it
   now* (`run-next`) and *later* (`later`); its detail names the brief and where it came from. Answered *run it now*,
   the new flow's run starts (queued behind another flow's when one is active); *later*, nothing. A next flow made
   again (`--make` when one exists) is refused, naming it.
5. **`next_flow`**, a setting of the flow: `ask` (the default), `run` (it starts at once, unasked), `off` (none is
   made).
6. **The brief's copy**, when the next flow's run 1 starts: the brief's text into its YOU box's first file, when that
   file's fingerprint is still `follows.replaces` (or it is still missing when it was); else kept. A brief no longer in
   the folder is said, and nothing copied.
7. **Commands:** `clank flow next NAME`: the next flow, its title and where its brief came from, whether it has run;
   else why none is made and how to make it. `--make`: make it now (from the latest run's INTEGRATE). `--run`: make it
   when there is none, then run it (answering the question if it waits).
