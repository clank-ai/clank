# M0.4: adapters, and Docker through the workspaces component: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (executed natively in the session that
> wrote it). As for M0.2 and M0.3, this plan gives the files, interfaces and tests by name and intent; the code is in
> the commits, written test-first.

**Goal:** the kernel's adapters (kinds of adapter, their lists, one contract test file per kind run against every
adapter of the kind, fixtures recorded from the real program), and the `workspaces` component's first part, Docker:
its status followed in the background, `docker.start` and `docker.stop` as operations, stopping asking first when
containers Clank did not start are running. `clank docker status`, `clank docker start` and `clank docker stop` are
clients of it.

**Architecture:** `clank/kernel/adapters.py` defines what every adapter is (`Adapter`: a name, a label, the platforms
it works on, what it supports for the version in use) and what a kind of adapter is (`AdapterKind`: its interface and
the list of its adapters). A component declares its kinds of adapter; the container platform kind belongs to the
workspaces component (`clank/components/workspaces/adapters/`), with Docker Desktop its first adapter. The adapter
runs Docker's own commands (`docker desktop start|stop|status`, `docker ps`) through a `run` function, so the contract
test drives it with what Docker Desktop 4.85.0 really answered (`tests/fixtures/docker-desktop/4.85.0/`). The
component's part (`Workspaces`) polls the adapter, records `docker.changed` when what runs changes, and runs the two
operations under one lock, `docker`.

**Tech Stack:** what M0.3 uses; nothing new.

**Spec:** [design 0002](../design/0002-the-foundation.md) §2.1 (a component's `adapters/`), §2.4 (operations: locks,
request keys, reconciling), §2.5 (questions), §2.9 (containers told apart by Clank's labels; Clank stops only what it
started), §2.10 (adapters), §3.2 (M0.4, and what M0's tests must prove: "no Clank action touches a container without
Clank's labels, and stopping Docker itself asks first"); design 0001 §4.6 (what Clank may stop), §8.2-8.3 (contract
tests, recorded fixtures); [PROTOTYPE.md](../PROTOTYPE.md) (Docker Desktop started after WSL removes WSL's
handler for Windows programs).

## Global Constraints

- Everything of M0.1-M0.3's global constraints holds.
- Tests never start or stop the Docker on the machine that runs them; they drive the adapter with recordings and the
  component with a fake platform. Reading the real Docker's status is allowed (the service's own tests run the real
  service, which polls it).
- A container is Clank's only when it carries `clank.home` with this CLANK_HOME's id. Clank never acts on a single
  container in M0.4; stopping Docker Desktop stops every container, so it asks first whenever one runs that is not
  Clank's, naming each (the prototype's marked as such).
- Recorded fixtures hold no personal value: container names, ids, images and labels are replaced by made-up ones; the
  secrets check runs over them like every file.

## Review Focus

1. **Stopping Docker while containers Clank did not start are running:** a question naming them, answerable from any
   client; "cancel" leaves Docker running, and the operation says it was canceled by that answer. Pinned by
   `test_stopping_docker_with_containers_clank_did_not_start_asks_first_and_cancel_leaves_it_running`.
2. **Docker Desktop is not installed, or too old for `docker desktop`:** the status says so, start and stop fail with
   what to do, nothing crashes. Pinned in Tasks 2 and 3.
3. **Docker does not come up within the time allowed, or the user cancels while it starts:** the operation fails with
   the time it waited, or ends canceled; neither leaves the `docker` lock held. Pinned in Task 3.
4. **Two clients press start at once:** one operation; the second gets the first (same request key) or is refused
   naming it (`busy`). Pinned in Task 3.
5. **The question is answered elsewhere while `clank docker stop` waits at its prompt:** the command says who answered
   and goes on with the operation. Pinned in Task 4.

### Task 1: Adapters in the kernel

**Files:** `clank/kernel/adapters.py`; `clank/kernel/components.py` (`adapter_kinds`); `clank/registry.py`
(`adapter_kinds()`); `clank/kernel/home.py` (`Home.id`); `tests/fakes/recorded.py`; tests `tests/kernel/test_adapters.py`,
`tests/kernel/test_home.py`, `tests/fakes/test_recorded.py`, `tests/test_architecture.py`.

**Interfaces:** `Capability(name, supported, how)`; `Adapter` (class attributes `NAME`, `LABEL`, `PLATFORMS`;
`capabilities() -> list[Capability]`, read from the program in use); `AdapterKind(name, summary, interface, adapters)`
(refuses an adapter that does not implement the whole interface, lacks a name, label or platform, or reuses a name),
`all()`, `get(name)`, `for_platform(platform)`; `AdapterError`. `Component(..., adapter_kinds=())`; `registry.adapter_kinds()`.
`Home.id`: twelve hexadecimal characters derived from the folder's resolved path, the same every time. `RecordedProgram`
(tests): loads a fixture folder's `program.json` (the program, its version, when and how it was recorded, its states,
and which commands move it from one state to another), answers a command as recorded for the current state, records
every call, and fails on a command that was never recorded.

**Tests:** a kind lists its adapters and finds them by name and platform; an adapter that misses a method of the
interface, or reuses a name, is refused; the home's id is stable and differs between homes; the recorded program
answers by state, moves on its transitions and refuses what was not recorded; the architecture test: every kind of
adapter has its contract test file, `tests/contract/test_<kind>.py`, and every adapter its recordings,
`tests/fixtures/<adapter>/<version>/program.json`.

### Task 2: The container platform kind, the Docker Desktop adapter, and `clank docker status`

**Files:** `clank/kernel/processes.py` (running a program to read its answer, moved from the machine component, which
now uses it from the kernel); `clank/components/workspaces/` (`component.py`, `kinds.py` with `DockerSettings`,
`service.py`, `api.py`, `cli.py`), `adapters/__init__.py` (the kind and its list), `adapters/platform.py` (the
interface), `adapters/docker_desktop.py`; `clank/components/__init__.py`; `tests/fixtures/README.md`,
`tests/fixtures/docker-desktop/4.85.0/program.json`; tests `tests/kernel/test_processes.py`,
`tests/contract/test_container_platform.py`, `tests/components/workspaces/conftest.py` (`FakePlatform`),
`tests/components/workspaces/test_docker_desktop.py`, `tests/components/workspaces/test_docker.py`,
`tests/cli/test_docker_commands.py`.

**Interfaces:** `run_command(arguments) -> str | None`, `decode(output)`, `Run` (kernel). `Container(id, name, image,
state, status, clank: dict[str, str], label_keys: list[str])`; `PlatformStatus(adapter, label, state, version, engine,
containers, detail)` with `running`; `ContainerPlatform(Adapter)`: constructed as `(run, command)` (`command` None when
the platform is not installed), `find()` (where its command is on this machine), `status()`, `request_start()`,
`request_stop()`, `after_start(log)`, each blocking and quick (the operation waits, not the adapter); `PlatformError`;
`LABELS` (`clank.home`, `clank.component`, `clank.record`); `CONTAINER_PLATFORMS`. `DockerDesktop`: the status reads
`docker desktop status --format json`, then, while it runs, `docker version` (Docker Desktop's and the engine's
versions) and `docker ps --all` with a template that gives Clank's labels exactly; start and stop are
`docker desktop start|stop --detach`; `after_start` on Windows puts back WSL's handler for Windows programs when WSL
runs and the start removed it (as the prototype does), and logs it. `DockerSettings(Settings)` (`config/docker.json`,
single): `adapter` (`docker-desktop`), `poll_seconds` (5), `start_timeout_seconds` (300), `stop_timeout_seconds`
(120), `question_minutes` (30). `owner(container, home_id)`: `clank`, `prototype` or `other`. `Workspaces(kernel)`:
`docker(refresh=False)` (the last status with each container's owner, and a one-line summary). Route `GET /docker`.
`clank docker status [--json]`.

**Tests (contract, every adapter of the kind, every recorded version):** running: its version, its engine's, its
containers with Clank's labels exactly and every label's name; stopped: no containers; a start and a stop ask the
program and change its state; without its command: not installed, and start is refused; capabilities are read from the
program. **Tests (Docker Desktop):** the command is found on the PATH or in Docker Desktop's folder; without `docker
desktop` (older than 4.37) the status says to update, and start is refused with that; after a start, a missing WSL
handler is put back and a present one is left alone; outside Windows nothing is asked of WSL. **Tests (the component):**
owners are told apart (this home's label, another home's, the prototype's labels or name, anything else); the route
shows the status with owners behind the token; `clank docker status` prints the state and each running container with
its owner, and JSON. **Tests (processes):** a command's output is returned; a failing or missing one gives None; UTF-16
output is decoded.

### Task 3: Starting and stopping Docker

**Files:** `clank/components/workspaces/service.py`, `api.py`, `component.py` (`docker.changed`);
`clank/kernel/operations.py` (`Canceled(reason)`); `clank/kernel/access.py` (`REQUEST_KEY_HEADER`); the machine
component's doctor route takes a request key too; tests `tests/components/workspaces/test_docker.py`,
`tests/kernel/test_operations.py`.

**Interfaces:** `Workspaces`: `operation_types()` (`docker.start`: steps `start`, `wait`; `docker.stop`: steps `check`,
`stop`, `wait`; both lock `docker`, both safe to repeat, both reconciled after a restart by reading the status),
`run()` (polls every `poll_seconds`, records `docker.changed` when what runs changes). Event type `docker.changed`
(data: the status without labels). Routes `POST /docker/start`, `POST /docker/stop` (the header `X-Clank-Request-Key`
makes a press sent twice start one operation). `Canceled("…")` carries the reason the operation shows.

**Tests:** the poller records `docker.changed` once per change, not per poll; start when stopped starts and waits until
the engine answers, then runs the adapter's aftercare; start when running is done at once; a start that does not answer
in time fails naming the time; canceling while waiting ends it canceled and frees the lock; stop with only Clank's
containers (or none) does not ask; stop with others asks, naming them, the prototype's marked; "stop" stops Docker;
"cancel" leaves it running and the operation says it was canceled by that answer; the same request key starts one
operation and a second start is refused as busy; not installed: start and stop fail with what to do; an interrupted
start is reconciled from the status; the routes answer behind the token.

**Tests:** start prints its steps and the end; stop asks at the terminal and an answer of no leaves Docker running; `--yes`
answers "stop" as you (cli); a question answered elsewhere while the prompt waits is reported with who answered.

## Rulings made while building

- **Setup.** As in M0.3: work on `main`, a self-review at the end, interfaces and tests in the plan. Cost if wrong: a
  weaker review.
- **Task 1.** A kind takes its adapters as an explicit list when it is declared, not through a decorator: a decorator
  registers on import, so the list would depend on which modules happened to be imported, and the kind's module would
  import its adapters' modules in a cycle. Cost if wrong: none.
- **Task 2.** Task 2 also built the component's skeleton (kinds, service, API, commands) and `clank docker status`:
  the architecture test requires every component folder to have its whole shape, so the adapter could not land alone.
  Running a program to read its answer moved to the kernel (`processes.py`, design 0002 §2.9), since two components
  need it and one may not use another's internals; the commands' shared helpers moved to `clank/cli/common.py`. Cost
  if wrong: none.
- **Task 3.** The first reading of Docker after the service starts is not recorded as `docker.changed`: it is the
  state clients load, not a change. Cost if wrong: the history does not say what Docker was doing at the start.
- **Task 4.** A command follows its operation by reading it and its log (a new route, `GET /operations/{id}/log`) a
  few times a second rather than through the event stream, where log lines are live-only and those written before the
  stream connected would be lost. Each log line now records the step that wrote it (kernel migration 0002), so lines
  print under their steps whatever the clock says. Found by a smoke run against the real Docker: the `clank` command
  now writes UTF-8 on every platform (a Windows pipe got the code page), and untagged images show the start of their
  id. Cost if wrong: a few requests a second while a command waits.

has its test, the adapter read the owner's real Docker Desktop 4.85.0 correctly (status only; nothing was started or
