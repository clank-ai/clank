# M1.7: taking models and engines off a host, and retiring NInfer: implementation plan

> At the owner's request (2026-10-13): "It would be nice to have the ability to delete models from Clank (with the
> ability to restore them by downloading them again and having the configurations saved)"; then, after
> [the measurement](../measurements/2026-10-13-ninfer-and-kvmem.md), "If NInfer-5080 is dramatically less useful as
> KVMem, then we should scrap the NInfer implementation, delete this so that we aren't taking up too much room, and
> just continue using KVMem while making sure that everything is built for me to be able to change the model out later
> on", and on 2026-10-13 at 21:10: "Go ahead and fully retire NInfer." As for M1, this plan gives the files, interfaces
> and tests by name and intent; the code is in the commits, written test-first.

**Goal:** a model's files and an engine can be taken off a host from the command line and the console, and brought
back; NInfer's files are then taken off this machine with them, and NInfer leaves Clank's code (decision 0034), with
everything still built for more than one serving setup and any model.

**Spec:** design 0003 §7.5 (written with this plan), §7.1-§7.2; design 0001 §7.4-§7.5; decisions 0010 (serving setups
are plug and play), 0030 (hosts), 0032 (environments of their own), 0034 (written with task 3).

## Global Constraints

- Nothing is deleted without a question that says what goes and what it frees, unless the user asked with `--yes`;
  what Clank did not put there (a file the user keeps elsewhere, an engine adopted where it was) is only forgotten.
- Nothing outside the host's Clank folder is deleted: the host's own script refuses any other path.
- The catalog keeps a model whose files are removed, and every preset stays: `clank model download` brings it back;
  `clank engine install` builds a removed engine again where Clank has its recipe.
- No GPU: the owner uses it (2026-10-13, "please make sure we are not using the GPU until I say so"). Nothing here
  starts an engine.

## Review Focus

1. **A file the user keeps outside Clank's folder** (an adopted model, an adopted engine): never deleted.
2. **A model or an engine a running slot uses**: refused, saying which slot and how to free it.
3. **A download cut off, or a file kept aside** (`.part`, `.bad`): removed with the file.
4. **An install whose engine Clank no longer knows** (after NInfer leaves): it can still be forgotten.
5. **The folders a removal empties**: removed up to the host's models or engines folder, which stays.

### Task 1: Removing a model's files and an engine

**Files:** `clank/components/runtime/modelfiles.py` (`runtime.remove`), `installing.py` (`runtime.uninstall`),
`launching.py` (`running_on`, `model_record`, `clank_folder`), `state.py` (`remove_install`), `api.py`, `cli.py`,
`console/providers.py`, `clank/console/data.py`; tests `tests/components/runtime/test_remove.py`,
`test_console_providers.py`, `tests/console/test_data.py`.

**Interfaces:** `POST /runtime/model-files/remove` {model, host, format?, role?, yes} and `POST
/runtime/installs/remove` {setup, version, host, yes}, each starting its operation; `clank model remove NAME --host H
[--format F] [--role R] [--yes]`, `clank engine uninstall SETUP --version V --host H [--yes]`; the Providers and models
page's `x` and `u`.

- [x] The tests, failing first; the operations, the routes, the commands, the console's keys.

### Task 2: NInfer off this machine

Use task 1's commands on the owner's machine: `clank model remove qwen3.8-27b --format ninfer --host ubuntu` (16 GB)
and `clank engine uninstall ninfer-rtx5080 --version v1.4 --host ubuntu` (3.6 GB, the recipe's folder).

- [x] Done 2026-10-13: 16.5 GB and 3.73 GB freed in `Ubuntu`, through the service's operations; a `download.log` left
  in the model's folder by the download of 2026-10-12 (not Clank's), and the folders it kept, were removed by hand.
  Windows sees the space again once the distribution's virtual disk is compacted, which needs the distribution
  stopped: the owner's to schedule.

### Task 3: NInfer out of the code

Its adapter, its recipe, its presets, its catalog file and sizes, its fixtures, the fake engine's NInfer style, and
every test that used it (a second KVMem preset takes its place where a test needs two); decision 0034; designs 0003 and
0004, ROADMAP, GLOSSARY. Measurements, decisions and finished plans keep what they recorded.

- [x] Done 2026-10-13: decision 0034. The rig's second preset is `fake KVMem small` (4K); the fake engine's
  `--fake-only-context` makes it fail where a test needs a failing switch, while `fake KVMem` starts from the same
  install.

## Rulings made while building

- **Task 1: a model's removal takes all its files on the host unless a format or a role is named**, as people think of
  "deleting a model"; each file is said in the question with its own way back. Cost if wrong: a flag to add.
- **Task 1: the engine command is `clank engine uninstall`**, the opposite of `install`; the model command is `clank
  model remove`, the opposite of `download`. Cost if wrong: a name.
- **Task 1: only what Clank made is deleted**: a model's file at its place in the host's models folder (with a `.part`
  or `.bad` left of it), an engine built by recipe in its own folder under the host's engines folder. A `model-file`
  record, an adopted engine, a test's, or a recipe install whose folder is elsewhere are forgotten without a question,
  since nothing is lost. Cost if wrong: the user deletes their own files themselves.
- **Task 1: a slot that runs something on the host refuses a removal it would break**, and one whose preset is gone
  refuses every removal on that host, since nothing says what it uses. Cost if wrong: an unload first.
- **Task 1: one size formatter** (`catalog.size_text`) replaces the console's and the model files' copies.
- **Task 3: the engine-neutral parts NInfer first needed stay** (the fit of an engine that sizes its own KV cache, and
  the estimate learning from what an engine needed to start), tested without an engine that uses them, since vLLM and
  SGLang would. Cost if wrong: about 60 lines kept for an engine that does not come.
- **Task 3: `Launch.model_name` goes** (only NInfer's adapter read it); the runtime setting `model_name` stays, as the
  name the gateway puts in each request. Cost if wrong: none.
- **Task 3: with no recipe shipped, the recipe loader has none** instead of failing on a missing folder; the tests of
  a shipped recipe wait for KVMem's. Cost if wrong: none.
- **Task 3: designs keep what they said of NInfer, marked retired**, as design 0003 §7.4 did for the prototype's
  profiles; the parts that describe the present (the catalog, the commands) say the present. Cost if wrong: longer
  designs.
