# M0.2: the kernel: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (this plan is executed natively in the session
> that wrote it; subagents only when the owner asks). Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **How this plan is written.** The owner asked to plan and build the rest of M0 in one go (2026-10-11). This plan
> therefore gives, for each task, the files, the interfaces (signatures and data shapes), the database schema, and the
> tests by name with what each asserts; the code itself is in the task's commit, written test-first, instead of being
> copied here as well. Ruling: cost if wrong: a reader of the plan alone sees less code; the commits hold all of it.

**Goal:** the kernel parts M0 uses, each with its tests: records (kinds of record, settings files), the state database,
events, operations and questions (design 0002 §2.2-2.5, as approved, including the revisions for the outside review).

**Architecture:** `clank/kernel/` holds one module per part. Each part takes what it needs explicitly (the store, the
event log, a clock), so tests build it with a temporary database and a fake clock. Settings are JSON files in
`CLANK_HOME/config/`; state is one SQLite database written through one `Store`; every change worth knowing is an event
in the same database. Operations run as asynchronous tasks (AnyIO) and wait for questions through the event-driven
answer path. `clank/registry.py` collects everything the kernel and the components declare (kinds, event types,
operation types), so generated documents and the service read one list.

**Tech Stack:** Python 3.12+, Pydantic 2.14 (decision 0015), AnyIO 4.15 (FastAPI's own dependency, decisions 0016 and
0022), SQLite (Python's standard library, decision 0014).

**Spec:** [design 0002 §2](../design/0002-the-foundation.md#2-the-kernel) (§2.2 records, §2.3 events, §2.4 operations,
§2.5 questions) and [§3.2](../design/0002-the-foundation.md#32-m0-the-skeleton) (M0.2).

## Global Constraints

- Everything in M0.1's global constraints holds (Python 3.12+, the lock, docstrings, tests that name design sections,
  American English, nothing personal, 120-character lines, a commit pushed per task).
- Settings are JSON files written in one fixed format: two-space indents, `"schema"` first, then the fields in the
  kind's order, only the values that differ from the defaults, LF line endings, a final newline (design 0002 §2.2,
  design 0001 §3.4).
- State is written only through `Store`; a migration is never edited once released (checked by its checksum).
- Times are UTC, written as ISO 8601 text with milliseconds and a `Z` (they sort as text).
- Every field of every kind has a label (`title`) and help (`description`): the explain key shows them.
- No event type is recorded unless declared; `docs/EVENTS.md` is generated from the declarations.
- Names mean one thing (principle 4): a record's kind is `kind`; the subtype of an event, an operation or a question is
  its `type`. Ruling: design 0002 §2.5 calls a question's approval/choice/text its `kind`; here it is `type`, because
  `kind` already names the kind of record. Cost if wrong: one field name.
- Tests need no network, use a temporary `CLANK_HOME` and a fake clock, and close every database they open.

## Review Focus

1. **A settings file a person edited by hand:** a byte-order mark, a trailing comma, a field of the wrong type, an
   unknown field, a missing `"schema"`: each is reported with the file, the line and the field, and the last good
   values stay in force. Pinned in Task 4.
2. **A crash between two writes that belong together** (an answer and its event): nothing half-written. Pinned by
   `test_an_event_and_another_write_commit_or_roll_back_together` (Task 2) and the question tests (Task 5).
3. **A client that was away for weeks** asks to resume from an event that was pruned: it is told to reload, not silently
   given a partial history. Pinned by `test_a_client_behind_the_pruned_events_is_told_it_missed_some` (Task 3).
4. **The same request twice** (a phone retrying): one operation, not two. Pinned by
   `test_the_same_request_key_returns_the_operation_already_started` (Task 6).
5. **An answer from another thread** (a web request handled off the event loop) wakes the waiting operation. Pinned by
   `test_an_answer_given_from_another_thread_wakes_the_operation` (Task 6).

### Task 1: Records, the clock and CLANK_HOME

**Files:** `clank/kernel/__init__.py`, `clank/kernel/clock.py`, `clank/kernel/home.py`, `clank/kernel/records.py`,
`clank/registry.py`; tests `tests/kernel/conftest.py`, `tests/kernel/test_clock.py`, `tests/kernel/test_home.py`,
`tests/kernel/test_records.py`; `pyproject.toml` (dependencies `pydantic>=2.14.1`, `anyio>=4.15.1`; mypy's Pydantic
plugin; `explicit_package_bases`, so that two `conftest.py` files do not collide).

**Interfaces:**
- `clock.Clock` (protocol: `now() -> datetime`), `SystemClock`, `FakeClock(start)` with `advance(seconds)` and `set(dt)`;
  `to_text(dt) -> str` ("2026-10-11T12:00:00.000Z"), `from_text(text) -> datetime`.
- `home.Home(root: Path)` with `config`, `secrets`, `state`, `logs`, `library`, `artifacts`, `database`; `Home.resolve(
  environ)` (`CLANK_HOME`, else `~/.clank`); `ensure()` creates the folders (`secrets/` and `state/` readable only by
  the user where the platform allows).
- `records.Kind` (Pydantic base: `KIND`, `LABEL`, `HELP` class constants; `extra="forbid"`), `records.Settings(Kind)`
  (`VERSION`, `SINGLE`, `FOLDER`, `ON_CHANGE` in "now" / "next start" / "refused", `MIGRATIONS`; field `title`),
  `records.StateKind(Kind)`; `records.Registry` (`add`, `get`, `all`, `settings`; refuses a kind declared twice or
  missing its constants); `records.undocumented_fields(model) -> list[str]` (walks nested models).
- `registry.kinds() -> Registry`, `registry.event_types()`, `registry.operation_types()`: the kernel's declarations
  (components join in M0.3).

**Tests:**
- `test_clock.py`: the fake clock moves only when told; times round-trip through text, in UTC, sortable as text.
- `test_home.py`: `CLANK_HOME` wins over the default; the default is `~/.clank`; `ensure()` creates every folder.
- `test_records.py`: a kind declared twice is refused; a kind missing `KIND`, `LABEL` or `HELP` is refused; a field
  without a label or help is found, in nested models too; every kind Clank declares has every field documented.

- [x] Write the tests; run them (fail: no module `clank.kernel`); write the modules; run every check; commit and push.

### Task 2: The state database

**Files:** `clank/kernel/store.py`, `clank/kernel/migrations/0001_kernel.sql`; test `tests/kernel/test_store.py`.

**Interfaces:**
- `Store(path: Path | None)` (None: in memory), WAL, foreign keys on; `transaction()` (a context manager; nested calls
  join the outer one; `BEGIN IMMEDIATE`, committed or rolled back as a whole); `read(sql, params) -> list[Row]`;
  `after_commit(callback)` (runs when the outermost transaction commits, dropped on rollback); `close()`.
- `Migration(owner, number, name, sql)`; `Store.migrate(migrations) -> list[str]` applies each once, in order, recording
  its checksum in `schema_migrations`; an applied migration whose text changed raises `MigrationError`.
- `kernel_migrations() -> list[Migration]` reads `clank/kernel/migrations/NNNN_name.sql`.

**The kernel's first migration** (`0001_kernel.sql`): `kernel_meta(key, value)`; `events(id INTEGER PRIMARY KEY
AUTOINCREMENT, time, type, subject_kind, subject_id, actor, summary, data)` with indexes by time, by type, by subject;
`operations(id, type, title, status CHECK in the seven statuses, started_by, created, updated, finished, cancelable,
params, result, error, request_key UNIQUE, locks, waiting_on, planned_steps, retry_of)`; `operation_steps(operation_id,
number, name, status, repeatable, started, finished, detail)`; `operation_log(operation_id, number, time, text)`;
`questions(id, type CHECK in approval/choice/text, status CHECK in waiting/answered/expired/withdrawn, about_kind,
about_id, asked_by, title, detail, options, default_option, expires, urgency, asked, answer, reason, operation_id)`.

**Tests (`test_store.py`):** migrations apply once and in order; running them again applies nothing; an applied
migration that was edited is refused; a failing migration leaves nothing behind; a transaction that fails writes
nothing; nested transactions commit together; after-commit callbacks run only after the outermost commit and never
after a rollback; the database file uses write-ahead logging.

- [x] Write the tests; run them (fail); write the store and the migration; run every check; commit and push.

### Task 3: Events

**Files:** `clank/kernel/events.py`; `tools/eventsdoc.py` and the generated `docs/EVENTS.md`; tests
`tests/kernel/test_events.py`, `tests/tools/test_eventsdoc.py`, one test in `tests/test_repository.py`.

**Interfaces:**
- `Actor(kind: user|device|session|process|clank, via: str)` with `describe()` ("you (console)", "Clank"); `CLANK`.
- `Subject(kind, id)`; `Event(StateKind)`: `id: int | None` (None when live only), `time`, `type`, `subject`, `actor`,
  `summary`, `data`.
- `EventType(name, help, fields: dict[str, str], live=False, owner="kernel")`; `EventTypes(types)` (`get`, `all`;
  refuses duplicates).
- `EventLog(store, clock, types)`: `record(type, *, summary, actor, subject=None, data=None) -> Event` (refuses an
  undeclared or live-only type; joins an open transaction; listeners hear it after commit); `publish_live(...)` (never
  kept); `subscribe(listener) -> unsubscribe`; `after(last_id, *, types=None, subject=None, limit=1000)`; `latest(limit,
  *, before=None, types=None, subject=None)`; `last_id()`; `missed(last_id) -> bool` (events after it were pruned);
  `prune(older_than) -> int` (remembers how far it pruned).
- `tools/eventsdoc.py` writes `docs/EVENTS.md` from `registry.event_types()` (`--check` as the other generators).

**Tests:** ids only grow, and an event reads back as it was written; an undeclared type is refused; a live-only type is
never kept but reaches listeners; resuming after an id returns only later events, filtered by type and subject;
listeners hear an event only after its transaction commits, and never one that rolled back; pruning removes old events
and `missed` tells a client behind them that it missed some (`test_a_client_behind_the_pruned_events_is_told_it_missed_
some`); the events page lists every declared type; the repository's `docs/EVENTS.md` is up to date.

- [x] Write the tests; run them (fail); write the module and the generator; generate; run every check; commit and push.

### Task 4: Settings files, and the service's settings

**Files:** `clank/kernel/settings.py`, `clank/kernel/kinds.py` (`ServiceSettings`, the kernel's kinds and event types),
`tools/schemas.py` and the generated `clank/schemas/service.schema.json`; tests `tests/kernel/test_settings.py`,
`tests/tools/test_schemas.py`, two tests in `tests/test_repository.py`.

**Interfaces:**
- `ServiceSettings(Settings)`: `KIND = "service"`, one record (`config/service.json`), applies at the next start;
  fields `host` ("127.0.0.1"), `port` (7720), `events_kept_days` (30), each with a label and help.
- `Loaded(kind, id, record, source: built-in|default|user, path, revision)`; `SettingsProblem(path, line, field,
  message)`; `SettingsError(message, current: Loaded | None)`.
- `SettingsFiles(home, kinds, *, events, clock, defaults=clank/defaults, in_use=None)`: `load() -> list[SettingsProblem]`
  (reads Clank's defaults, then the user's files, which replace a default of the same name; an invalid file keeps the
  last good values and is reported as `settings.invalid`); `list(kind)`, `get(kind, id)`; `write(kind, id, values, *,
  base, actor) -> Loaded` (validates, refuses a stale `base` revision, refuses a change to a record in use when the
  kind says so, writes the fixed format atomically, records `settings.changed` with each field's old and new value);
  `delete(kind, id, *, base, actor)`; `reload_changed() -> list[Event]` (files edited on disk, recorded as changed by
  "you (file)"); migration of an older file to the kind's version, keeping the original beside it as
  `<name>.v<N>.json` (`settings.migrated`).
- `render(record, kind) -> str`: the fixed format.
- `tools/schemas.py` writes `clank/schemas/<kind>.schema.json` for every settings kind: the kind's JSON Schema plus the
  `"schema"` property.

**Tests (`test_settings.py`):** a single-record kind with no file gives its built-in values; a user file replaces
Clank's default file of the same name; the fixed format; a byte-order mark is accepted; invalid JSON is reported with
its line and the last good values stay; a wrong type and an unknown field are reported with file, line and field; a
file without `"schema"`, or naming another kind's, or a newer version, is reported; an older version is migrated and
the original kept; a write based on an old revision is refused with the current version; a change to a record in use
is refused when its kind says so; a write records each field's old and new value; a file edited on disk is reloaded and
recorded as changed by a person; deleting a user file brings Clank's default back. `test_schemas.py`: a settings
kind's schema carries its fields, their labels and help, and the `"schema"` constant. Repository: the schemas in
`clank/schemas/` are up to date; every JSON file under `clank/defaults/` reads as its kind.

- [x] Write the tests; run them (fail); write the modules and the generator; generate; run every check; commit, push.

### Task 5: Questions

**Files:** `clank/kernel/questions.py`; test `tests/kernel/test_questions.py`.

**Interfaces:**
- `Option(id, label, effect, key)`; `QuestionDraft(type: approval|choice|text, title, detail, options, default, expires,
  urgency: normal|high, about: Subject | None)` (approval and choice need two options or more; option ids are unique;
  the default is one of them; an expiry needs a default); `Answer(option, text, by: Actor, time)`;
  `Question(StateKind)`: the draft's fields plus `id` ("q-" and six hex digits), `status`
  (waiting|answered|expired|withdrawn), `asked_by`, `asked`, `answer`, `reason`, `operation_id`.
- `Questions(store, events, clock)`: `ask(draft, *, asked_by, operation_id=None) -> Question` (`question.asked`);
  `answer(id, *, by, option=None, text="") -> Question` (once; `question.answered`); `withdraw(id, *, reason, by)`;
  `expire_due() -> list[Question]` (the default becomes the answer; `question.expired`); `get`, `waiting`, `list`;
  `on_resolved(listener) -> unsubscribe` (heard after commit, from whichever thread resolved it).

**Tests:** asking records the question and an event; an answer records who gave it, from which client, and when; a
second answer is refused, naming the first; an answer must be one of the options, and a text question needs words or a
suggestion; a draft without enough options, or with a default that is not an option, is refused; a question whose time
is up takes its default and says so; a withdrawn question cannot be answered; questions survive reopening the
database; listeners hear an answer after it is recorded.

- [x] Write the tests; run them (fail); write the module; run every check; commit and push.

### Task 6: Operations

**Files:** `clank/kernel/operations.py`; test `tests/kernel/test_operations.py`.

**Interfaces:**
- `Step(number, name, status: running|done|failed, repeatable, started, finished, detail)`;
  `Operation(StateKind)`: `id` ("op-" and eight hex digits), `type`, `title`, `status` (queued, running, waiting,
  done, failed, canceled, interrupted), `started_by`, `created`, `updated`, `finished`, `cancelable`, `params`,
  `result`, `error`, `request_key`, `locks`, `waiting_on`, `planned_steps`, `steps`, `retry_of`; `progress()`
  ("2 of 3: stop").
- `StepSpec(name, repeatable=True)`; `Reconciliation(note)`; `OperationType(name, title, steps, run, reconcile=None,
  cancelable=True, locks=lambda params: (), owner="kernel")`.
- `OperationContext`: `params`, `actor`, `step(name)` (an async context manager recording the step's start and end, or
  its failure), `log(text)`, `ask(draft) -> Answer` (waits for the user; status `waiting`), `check_canceled()`,
  `run_blocking(fn, *args)`.
- `Operations(store, events, questions, clock, types)`: `running()` (an async context manager owning the task group);
  `start(type, params=None, *, actor, request_key=None) -> Operation`; `get`, `list`; `cancel(id, *, actor)`;
  `recover() -> list[Operation]` (at the service's start: queued, running and waiting operations become interrupted,
  their open questions are withdrawn, and each type's reconcile records what actually happened); `retry(id, *, actor)`
  (only when every step that had started is safe to run again). Errors: `OperationError`, `Busy`, `Canceled`.

**Tests:** an operation runs its steps in order, records each step's start and end, its progress and its result, and
announces each change; a failing step fails the operation and stops it; a second operation needing the same lock is
refused, naming the first and who started it; `test_the_same_request_key_returns_the_operation_already_started`;
canceling stops a cancelable operation at its next check, and an operation that cannot be canceled says so; waiting
for the user sets `waiting`, and the answer resumes it; `test_an_answer_given_from_another_thread_wakes_the_operation`;
an expired question resumes it with the default; after a restart, unfinished operations are interrupted, their
questions withdrawn and their reconcile recorded; retrying an interrupted operation runs it again when its steps are
repeatable and is refused when a step that had started is not.

- [x] Write the tests; run them (fail); write the module; run every check; commit and push.

## Rulings made while building

- **Setup.** Work on `main`; the final review is a self-review (the owner: no subagents unless asked). Cost if wrong: a
  weaker review.
- **Setup.** The plan gives interfaces and tests; the code is in the commits. Cost if wrong: the plan alone shows less.
- **Setup.** A question's approval/choice/text field is `type`, not `kind`. Cost if wrong: one field name.
- **Plan commit.** The plan was pushed once with a British spelling that the new check reported; fixed in
  the next commit, and since then every commit goes through a helper that commits only when every check passes.
- **Task 2.** Ruff's PT012 wants one statement per `pytest.raises` block: the deliberate failures became helper
  functions. **Task 3.** One compound assertion split (PT018). Cost if wrong: none.
- **Task 4.** `SettingsFiles.records(kind)` and **Task 5** `Questions.find()` instead of `list`, which shadowed the
  built-in inside the class; `ServiceSettings` lives in `clank/kernel/service.py`, the service's own module. Cost: none.
- **Task 6.** Two of my test mistakes were fixed before the code (the retry-refused test now starts its unsafe step; no
  test-only method), and every wait in the tests is bounded so a broken test fails instead of hanging. The first test
  found a real bug (a step's end recorded without its name); AnyIO's own name for its cancellation exception keeps
  its British spelling, with a `spelling: keep` marker on that line. Cost if wrong: none.

## Final review

A self-review of all of M0.2 against design 0002 §2.2-2.5 and the Review Focus above: every Review Focus item has its
test, and CI passed (run 38192697947). No important finding. Deferred (minor): a question's option keys are not checked
for being distinct; a settings error's line is the first line naming the field, which can miss for nested or repeated
keys; the lock table knows only the operations this service started (right for one service); `latest()` pages by id.
