# M1.6: both serving setups on this machine: implementation plan

> As for M1.1-M1.4, this plan gives the files, interfaces and tests by name and intent; the code is in the commits,
> written test-first.

**Goal:** both serving setups start, answer, switch and stop through Clank on this machine, with what they took
measured; the real-engine tests (`-m real`) run them on demand; the console's layout and keys if room is left; the
documents brought up to date, and version 0.2.0.

**Architecture:** design 0003 §9: real engines run on this machine only, when asked, and only when the GPU holds no
engine and port 18200 is free; they stop what they started, and the owner's models are never touched.

**Spec:** [design 0003](../design/0003-the-runtime.md) §5, §6 and §9; design 0001 §3.6.

## Global Constraints

- Everything of M1.4's global constraints holds.
- A real launch starts only when the GPU holds no engine and port 18200 is free, and stops what it started.

## Review Focus

1. **A switch right after a stop:** the port and the GPU's memory are freed a moment after the engine ends (WSL's
   relay, the driver); the start that follows must not take them for another program's. Pinned in Task 1.
2. **An engine that reserves more than it touches** (NInfer): the next estimate learns from what it needed to start,
   not from what it took. Pinned in Task 1.
3. **A preset that cannot run on this machine:** its check says so before anything starts. Pinned in Task 1.
4. **A real test on a machine whose GPU is in use:** it is skipped, saying why, and starts nothing. Pinned in Task 2.
5. **A real test that fails midway:** what it started is stopped all the same. Pinned in Task 2.

### Task 1: The first launches on this machine (done 2026-10-13, ahead of M1.5)

**Ruling:** moved ahead of M1.5: what a real launch teaches (the engines' own words, their memory) feeds the console's
pages, and M1.4 had just put both setups on this machine.

What they found, each fixed with a test that failed first:

- WSL's relay (`wslrelay.exe`) goes on listening on Windows' side of a port for about a second after the program in
  WSL ends, so the start that followed a stop saw the port held (583c155).
- NInfer refuses a chat request that names no model: the health check names the model `/v1/models` lists (f627a17).
- NInfer v1.4 holds the whole context in its KV cache for each request at a time; its MTP head keeps a KV cache of its
  own (18,496 bytes a token in all); beside this desktop it has about 1,660 MiB free after its weights. The published
  128K profile cannot start here, and neither could the "fitted" one, whose capacity `auto` cannot shrink: *NInfer 44K
  fitted* (context and capacity 45,056) replaces it, and a capacity below the context is refused (f627a17).
- The driver frees a stopped engine's memory a moment after it ends (6.6 GB still in use right after KVMem stopped):
  a stop now waits, up to 30 seconds, for the GPU to free what the engine took (0c22e2a).
- NInfer reserves more than it touches (took 13,486 MiB, needed 14,188 to start): a launch keeps what its engine says
  it needed, and the next estimate learns from that (0c22e2a).

Measured (2026-10-13, desktop at 1.3-1.7 GB, one 400-token answer to a 33-token prompt, thinking off, twice each; the
fuller comparison of the same day is [a measurement of its own](../measurements/2026-10-13-ninfer-and-kvmem.md), and its
KVMem writing speeds, 45-97 tokens a second, show the 25 below was low):

| Preset | Ready in | GPU taken | Needed to start | Answer speed |
| --- | --- | --- | --- | --- |
| *daily 262K* (KVMem v0.16.0-rc1, adopted) | 15-27 s | 13,714-14,284 MiB | | 25.3-25.8 tokens/s |
| *NInfer 44K fitted* (NInfer v1.4, built by its recipe) | 11-14 s | 13,479-13,486 MiB | 14,188-14,340 MiB | 55.6-63.9 tokens/s |

### Task 2: The real-engine tests

**Files:** `tests/real/test_engines.py`, `tests/real/conftest.py`; the `real` marker in `pyproject.toml`.

**Interfaces:** `uv run pytest -m real`: for each preset Clank ships whose engine is installed here, check it, load it,
ask it something, measure it, and unload it, through a service of its own (a temporary CLANK_HOME with this machine's
host, install and model-file records copied in).

**Tests:** skipped, saying why, when the GPU holds an engine or port 18200 is held; what a test started is stopped even
when it fails midway.

**Done 2026-10-13:** `uv run pytest -m real` on this machine: *daily 262K* and *NInfer 44K fitted* each started,
answered, were measured and stopped, and *NInfer 128K as published* was refused by its check (3 passed in 44 s; the
GPU back to 1.35 GB after). Without `-m real` they are skipped, saying how to run them.

### Task 4: Documents, and version 0.2.0

ROADMAP (M1 done), the plans index, the design's statuses; the 3.14 matrix run on demand; the tag.

**The matrix run found two things (2026-10-13)**, each fixed with a test that failed first. Python 3.14 warns about
the response of an HTTP error a test catches and leaves open. And on Linux the local host now and then took its own
engine for another process (the launches test failed about once in thirty runs, on CI and in a Linux container here):
a load then failed ("ended while it started"), or a stop said "gone" and left the engine running, so the switch that
followed found its port held. Two races: the start psutil gives a process on Linux adds the boot time read now, which
moves by whole seconds whenever the system clock is set (a virtual machine's host sets it every few seconds); and for
a moment after a start, Linux can show the new process's command line empty. The local host now takes the start in
clock ticks from the boot (as the WSL host does) and waits until the process shows the command line it was started
with; the launches test then passed 200 runs out of 200 on Linux.

## Rulings made while building

- **Task 1 ran before M1.5**, for the reason above.
- **Task 3: the console's layout and keys move to M2**, as design 0003 §1 allows. M1's core took the room: both
  serving setups built, adopted and measured on this machine, five runtime bugs that only real engines showed, and the
  four runtime pages. The layout (which panels show, their order and size, the file each is in) and the keys
  (`config/keys.json`) are their own piece of design (design 0001 §5.5), and M2's trials bring more panels to lay
  out. The menu's *Layout* entry now says M2. If wrong, the console's look stays fixed (but for
  `config/console.tcss`, which M0 already reads) one milestone longer.

## Final review

Self-review (no subagents), 2026-10-13, against the review focus: a switch right after a stop waits for WSL's relay
and the GPU's memory (test_load, test_switch, and the real switches in both directions); NInfer's next estimate
learns from what it needed to start (test_model_commands); a preset that cannot run here is refused by its check
(the real tests: the published NInfer profile); a real test on a busy GPU is skipped, saying why (its fixture); a real
test that fails midway still stops what it started (its fixture's `finally`). Design 0003 §1's list of what M1's
tests must prove holds: Clank stops only what it started (process identity, the hosts' contract); a failed switch
returns to the last configuration that worked (test_switch, and once for real when the GPU had not yet been freed);
a running engine is adopted after a restart of the service (test_watcher, and on this machine after each restart of
the service); what each engine supports is read for its version and options (the adapters, their recordings); KVMem
and NInfer pass one contract, now on NInfer's real `--help` and startup; an install or a download asks first and
verifies what it got (test_install, test_download, and NInfer's build and model file here); a switch never starts an
engine while another program holds the GPU memory it needs or its port (test_load, test_switch).

Deferred minors:
- NInfer's fitted preset is fitted to this desktop's 1.6 GB; a desktop that holds more makes its check say it does not
  fit (as it should), and nothing suggests the context that would.
- The real tests copy the machine's installs from its state database by reading the table directly, not through the
  service's API.
