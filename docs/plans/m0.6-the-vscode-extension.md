# M0.6: the VS Code extension's shell: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (executed natively in the session that
> wrote it). As for M0.2-M0.5, this plan gives the files, interfaces and tests by name and intent; the code is in the
> commits, written test-first.

**Goal:** the Clank extension for VS Code (`vscode/`): it connects to the Clank service, shows Clank and Docker in the
status bar, lists the questions waiting and answers them (a question asked while VS Code is open also shows as a
notification with its options), starts and stops Docker, and tells the service when the user is typing. The same
question can be answered from VS Code or from the console, and each shows who answered.

**Architecture:** the extension is a client of the API and holds nothing of its own (design 0002 §1). Its core
(`vscode/src/core/`) never imports `vscode`: `connection.ts` finds CLANK_HOME and reads the connection file and the
local token; `client.ts` calls the API and follows the event stream (Server-Sent Events, resuming from the last event
seen); `state.ts` keeps what the extension shows, updated from the events; `controller.ts` decides what to show and
what each command does, through a `Presenter` interface. `src/extension.ts` is the thin glue: it implements the
presenter with VS Code's status bar items, quick picks and notifications, and registers the commands. The types of
Clank's kinds are generated (`src/core/kinds.ts`, decision 0028).

**Tech Stack:** TypeScript 7.0, `@types/vscode` 1.138, `@types/node` 22, Node's test runner; `tools/tstypes.py` and
`tools/vsix.py` (decision 0028, new); Node 22 in CI.

**Spec:** [design 0002](../design/0002-the-foundation.md) §1 (clients hold no state), §2.2 (types generated from each
kind), §2.5 (questions answered from any client), §2.7 (callers, the local token, presence), §2.16 (`vscode/`), §3.2
(M0.6); decision [0015](../decisions/0015-kinds-defined-once-in-pydantic.md).

## Global Constraints

- Everything of M0.1-M0.5's global constraints holds.
- The extension never stores a token or a record; it reads the local token from CLANK_HOME each time it connects.
- It calls the API with `X-Clank-Client: vscode`, so what it does is recorded as you (vscode); a request that starts an
  operation carries a request key.
- The core is tested without VS Code; the glue holds no logic a test would need.
- `tools.check` runs the extension's checks; a machine without Node is told what to install.

## Review Focus

1. **The service is not running when VS Code starts, or stops while it runs:** the status bar says so, and the
   extension connects when the service is back. Pinned in Tasks 2 and 3.
2. **A question is answered in the console while its notification is open in VS Code:** choosing an option then says
   who answered already. Pinned in Task 3.
3. **The event stream arrives in pieces that split a message, or several messages in one piece:** each message is read
   whole, once. Pinned in Task 2.
4. **CLANK_HOME is set, or a setting names it:** the setting wins, then the environment, then `~/.clank`. Pinned in
   Task 2.
5. **Typing fast:** presence is sent at most once a minute. Pinned in Task 3.

### Task 1: The extension's project, its types, and its checks

**Files:** decision record `0028-the-vscode-extensions-tools.md` and its index row; `vscode/package.json`,
`vscode/package-lock.json`, `vscode/tsconfig.json`, `vscode/README.md`, `vscode/.gitignore`; `tools/tstypes.py`,
`vscode/src/core/kinds.ts` (generated); `tools/check.py` (the extension's checks; `--fix` writes the types);
`.github/workflows/checks.yml` (Node 22); tests `tests/tools/test_tstypes.py`, `tests/test_repository.py` (the types are
up to date), `vscode/test/kinds.test.ts`.

**Interfaces:** `typescript_of(schema) -> str` (one interface per kind and per definition it uses: strings, numbers,
booleans, arrays, objects of a known shape and maps, nullable values, literal choices, date-times as strings);
`render(kinds) -> str`; `main()`. npm scripts: `build` (tsc), `test` (node --test on `out/test`), `check` (both).

**Tests:** each kind of JSON Schema maps to its TypeScript (required and optional fields, `null`, literals, arrays,
maps, references); the generated file is up to date; the generated types compile and a question read from JSON fits
them; `tools.check` runs the extension's checks, and without npm says how to get it.

### Task 2: The core: connection, client, events, state

**Files:** `vscode/src/core/connection.ts`, `client.ts`, `events.ts`, `state.ts`; tests `vscode/test/*.test.ts`,
`tests/vscode/test_client.py` (the client against a real service, through `vscode/out/test/live.js`).

**Interfaces:** `clankHome(setting, environment, homedir)`; `readConnection(home) -> {url, token} | undefined`;
`ClankClient(url, token, fetch)` with `get`, `post(path, body, requestKey?)`, `events(after, signal)` (an async
generator of `ServerEvent {name, id, data}`), `ClankError {status, code, message}`, `NotRunning`; `parseEvents` (a
stateful reader of the stream's text: messages across pieces, comments skipped); `State` (`service`, `docker`,
`questions`, `connected`, `apply(event)` returning the topics it changed).

**Tests:** CLANK_HOME from the setting, the environment, then the home folder; a missing or unreadable connection file
means not running; the client sends the token and `X-Clank-Client: vscode`, turns the API's error shape into
`ClankError`, and a refused connection into `NotRunning`; the stream's messages are read whole whether split or joined,
with ids and names; state follows question, Docker and service events; against a real service, the client lists a
waiting question and answers it, recorded as you (vscode).

### Task 3: The controller, the status bar and the commands

**Files:** `vscode/src/core/controller.ts`, `vscode/src/core/presenter.ts`, `vscode/src/extension.ts`; tests
`vscode/test/controller.test.ts`.

**Interfaces:** `Presenter` (`clank(text, tooltip)`, `docker(text, tooltip)`, `ask(question) -> option id`,
`pick(items, placeholder)`, `info(text)`, `warn(text)`); `Controller(presenter, connect, clock)` with `start()`,
`stop()`, `questions()`, `docker(action)`, `typing()`. Commands: `clank.questions`, `clank.dockerStart`,
`clank.dockerStop`, `clank.docker` (a pick of the two), `clank.reconnect`. Setting: `clank.home`.

**Tests:** the status bar shows the service's state and the questions waiting, and Docker's state; with no service it
says not running and connects once one answers; a question asked shows as a notification, and the option chosen answers
it as you (vscode); an option chosen after the question was answered elsewhere says who answered; the questions command
lists them and answers the one picked; Docker start and stop start their operations with a request key; typing sends
presence at most once a minute.

### Task 4: The package, and the records up to date

**Files:** `tools/vsix.py`; tests `tests/tools/test_vsix.py`; `AGENTS.md` (the extension, its checks, installing it),
`README.md`, `docs/ROADMAP.md` (M0 done), `docs/plans/README.md`, `docs/GLOSSARY.md`, the generated documents.

**Interfaces:** `build_vsix(folder, output) -> Path`: `extension.vsixmanifest`, `[Content_Types].xml` and
`extension/` (package.json, README, the compiled files).

**Tests:** the package holds the manifest naming the extension, its version and its VS Code engine, the content types,
and the compiled files; nothing from `node_modules` or the tests.

## Rulings made while building

- **Setup.** As in M0.5: work on `main`, a self-review at the end, interfaces and tests in the plan. Cost if wrong: a
  weaker review.
- **Task 1.** The generated interfaces mark every field present: Pydantic's serialization schema still calls a
  defaulted field optional, but the API always sends records whole. The code map and the tests page now cover the
  extension's TypeScript modules and tests (a leading comment instead of a docstring; test names that are sentences).
  Cost if wrong: none.
- **Task 2.** A test in the Python suite runs the compiled client with Node against a real service, so the client is
  proven against the API it talks to, not only against fakes. Cost if wrong: Node is needed for the full suite (it is
  skipped without it).
- **Task 4.** The extension prefers to run on the local machine (`extensionKind: ui`), beside the service, even when VS
  Code works in WSL or over SSH; the package was checked with VS Code's own installer, into a throwaway extensions
  folder, so the owner's VS Code was not touched. Cost if wrong: none.

## Final review

A self-review of all of M0.6 against design 0002 §1, §2.2, §2.5, §2.7, §3.2 and the Review Focus above: each Review
Focus item has its test (no service and a service back, an answer given elsewhere first, a stream split or joined,
CLANK_HOME's precedence, presence at most once a minute); the client answered a real service's question, recorded as
you (vscode); VS Code accepted the package; CI passed (run for a83672f). No important finding. Deferred (minor): no
test runs the glue inside a real VS Code (`@vscode/test-electron`, which decision 0028 leaves to M6); questions
already waiting when VS Code opens show in the status bar's count, not as notifications; the extension is not
installed in the owner's VS Code (one command, `code --install-extension vscode/clank-0.1.0.vsix`).

The version tag's run, the first on Python 3.14 since M0.1 (pushes to main run 3.12 only, decision 0022), then failed
on Linux and Windows; each cause is fixed in version 0.1.1, test-first:

- A service stopping with a client following the event stream cut that response after the two seconds' grace and
  logged the error (on every Python; 3.14's longer traceback filled the test helper's unread pipe and hung it). The
  server now closes the streams before it waits: each says `closing` and ends, and the stop takes a fraction of a
  second. `clank events --follow` ends on it with "(the service stopped)"; the test helper reads the output as it comes.
- The doctor's database check left its connection open (`with` on a connection commits; it does not close it), which
  Python 3.14 reports when the connection is collected. It is closed now; a run of the whole suite recording every
  connection found no other.
- A test of a settings file with a trailing comma expected Python 3.12's line for the error (3.14 names the comma's own
  line); it uses a missing comma now, which every version places on the same line.
