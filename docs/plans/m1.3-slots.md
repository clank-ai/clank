# M1.3: slots: load, unload, switch, return, crashes, adoption, memory: implementation plan

> As for M1.1 and M1.2, this plan gives the files, interfaces and tests by name and intent; the code is in the commits,
> written test-first.

**Goal:** the main slot runs a preset: `runtime.load`, `runtime.unload` and `runtime.switch` are operations with the
steps of design 0001 §4.2; a switch whose new preset fails goes back to the last configuration that worked; a watcher
notices a crash, restarts once when it may, and adopts a running engine after the service restarts; every launch is
recorded with the memory it was estimated to take and the memory it took, and the next estimate learns from the
difference; `runtime.check` checks a preset without starting anything. The API, `clank model ...` and `clank preset
check` drive them.

**Architecture:** design 0003 §6. The runtime component gets its own tables (`slots`, `launches`, `installs`,
migration `runtime 0001`) and two state kinds, `slot` and `launch`, which the record routes read through the part
(M0's item 13: a part reads its own state kinds). A launch is planned from the preset, its engine adapter, the catalog,
the install of the engine on a host, and where the model's files are there (a `model-file` record, else the host's
`models/` folder). The GPU is read with `nvidia-smi`. A slot's state changes only inside an operation or the watcher,
each change recorded as an event (`runtime.slot`).

**Tech Stack:** what M1.2 uses; `httpx2` (decision 0026) for the engines' API.

**Spec:** [design 0003](../design/0003-the-runtime.md) §3, §6; design 0001 §3.6, §4.1-§4.4, §4.6; design 0002 §2.2,
§2.4.

## Global Constraints

- Everything of M1.2's global constraints holds.
- A start never begins while another program holds the engines' port, or while the GPU's free memory is short of the
  plan because another program uses it; it says which, and never stops it.
- An engine Clank did not start is never stopped, adopted or restarted.

## Review Focus

1. **The new preset fails at its start, or its health:** what it started is stopped, the last configuration that worked
   is started again, and the operation says why the new one failed, with the engine's last log lines. Pinned in Task 4.
2. **The service restarts while an engine runs:** the engine is adopted, not restarted; one that ended meanwhile leaves
   the slot stopped, saying so. Pinned in Task 5.
3. **An engine crashes twice within an hour:** restarted once (if it had been ready ten minutes), then left failed with
   a question to the user. Pinned in Task 5.
4. **Port 18200 held by the prototype's own KVMem:** the start is refused, naming it. Pinned in Task 3.
5. **A second load or switch while one runs:** refused as busy, naming the first (the slot's lock). Pinned in Task 3.

---

### Task 1: The runtime's state, and its records

**Files:** `clank/components/runtime/migrations/0001_runtime.sql`, `clank/components/runtime/state.py`,
`clank/components/runtime/kinds.py`, `clank/kernel/api.py` (a part reads its own state kinds); tests
`tests/components/runtime/test_state.py`.

**Interfaces:** state kinds `SlotRecord`, `LaunchRecord`, `InstallRecord`; `RuntimeState` (`slot(name)`,
`set_slot(...)`, `launches(limit)`, `add_launch(...)`, `finish_launch(...)`, `installs()`, `add_install(...)`), event
type `runtime.slot`; a part's `read_records(kind)` and `read_record(kind, id)`.

**Tests:** a new slot is stopped; each change of state is kept with its reason and announced; launches and installs
are kept; `GET /records/slot` and `/records/launch/{id}` read them through the part.

### Task 2: The GPU, the plan of a launch, and the check

**Files:** `clank/components/runtime/gpu.py`, `clank/components/runtime/launching.py`; tests `test_gpu.py`,
`test_check.py`.

**Interfaces:** `gpu_memory(run) -> GpuMemory(total_mib, used_mib) | None`; `fit(estimate, gpu, tight_mib) ->
Fit(verdict, spare_mib, lines)`; `prepare(preset, ...) -> Prepared(plan, host, install, log)`; `Runtime.check(name)
-> list[CheckItem]` (each passed or failed with its reason): the preset's problems, the install, the model's files on
the host (size, and the checksum once), the program's `--help` listing every flag, and the fit.

**Tests:** `nvidia-smi`'s answer is read, and its absence is "unknown"; a fit is *fits*, *tight* or *does not fit*
with the breakdown; a check names each item that fails and starts nothing.

### Task 3: Load and unload

**Files:** `clank/components/runtime/slots.py`, `service.py`, `api.py`, `cli.py`; tests `test_load.py`.

**Interfaces:** operations `runtime.load` (plan, start, health, measure) and `runtime.unload` (stop) under the lock
`slot:<name>`; `POST /runtime/slots/{slot}/load`, `/unload`; `clank model load|unload|status`.

**Tests (fake engines on the local host):** a load starts the engine by its plan, waits until it is ready and answers
a tiny request, measures its memory, and the slot is ready with its identity; an unload stops it; a port held by
another program refuses the start naming it; a second load while one runs is refused as busy.

### Task 4: Switch, and the return to the last configuration that worked

**Files:** `slots.py`; tests `test_switch.py`.

**Interfaces:** `runtime.switch` (plan, stop, start, health, measure; return on failure); the last configuration that
worked, kept with the slot.

**Tests:** a switch replaces the engine; one whose engine fails at its start (out of GPU memory) or never becomes ready
goes back to the last configuration that worked and says why, with the engine's last lines.

### Task 5: The watcher: crashes, the restart, adoption

**Files:** `slots.py` (the part's `run`); tests `test_watcher.py`.

**Tests:** an engine that ends while ready makes the slot failed with its last lines; it is started again once when it
had been ready ten minutes; a second crash within the hour leaves it failed and asks; after a restart of the service
a running engine is adopted, and one that ended is said to have stopped while the service was not running.

### Task 6: What a launch teaches, and the commands

**Files:** `launching.py`, `cli.py`; tests `test_learning.py`, `test_model_commands.py`.

**Tests:** the next estimate for an engine on a host is corrected by the difference the last launch measured; `clank
preset check`, `clank model status`, `load`, `unload` and `switch` follow their operations and print the result.

- [x] Tasks 1-6, each test-first, each committed and pushed; CI green at the end.

## Rulings made while building

- **Setup.** As in M1.2. Cost if wrong: a weaker review.
- **Task 1.** A component's part reads its own state kinds (`read_records`, `read_record`), and the record routes ask
  the parts after the kernel's own kinds: M0's item 13, closed. Cost if wrong: none.
- **Task 2.** A preset may name its host; empty, it runs on the one host its engine is installed on. The check compares
  a model file's size; its checksum is verified once, when it is downloaded or adopted (M1.4). Cost if wrong: a file
  of the right size but other contents passes the check until then.
- **Task 3.** The tiny request passes with any answer that has choices: a thinking model may spend its 16 tokens
  thinking. The port is checked on the engine's host and, for WSL, on Windows, where WSL's ports also answer. A plan
  that does not fit is refused unless the request says `anyway`. `start_seconds` may be as low as 1 (tests, and engines
  that start fast). Cost if wrong: none.
- **Task 4.** A switch whose new engine fails ends failed even when the return brings the old one back (the switch did
  not happen); the return starts the last configuration that worked with the options it had then, in a step of its
  own. Cost if wrong: none.
- **Task 5.** A restart is an operation (`runtime.restart`) the watcher starts, so every client sees it; one that
  crashed less than ten minutes after its start is left failed, since it would likely crash again; the health check
  reads `/v1/models`, which costs the engine nothing, every 30 seconds; an adopted engine keeps when it became ready.
  Cost if wrong: an engine that crashes young is not started again by itself.
- **Task 6.** What a launch teaches is its own part of the estimate (`learned_mib`), and a launch keeps the adapter's
  own estimate, so corrections never add up on each other. Cost if wrong: none.

## Final review

A self-review of M1.3 against design 0003 §3 and §6, design 0001 §3.6 and §4, and the Review Focus above: each item has
its test (a failing switch returns, adoption after a restart, a second crash asks, a port another program holds, a
second load while one runs); every operation was run end to end with the fake engines on the local host; CI passed.
No important finding. Deferred (minor): the busy check of a switch (requests in flight) waits for the gateway, which
sees them (M3); a crash is noticed within five seconds, not at once; the restart's question expires after 30 minutes
with its default (leave it stopped).
